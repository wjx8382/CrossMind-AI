# CrossMind AI Demo 指南

## 演示目标

建议将复赛视频控制在 **3 分 30 秒至 4 分钟**，重点证明四件事：产品解决明确问题、四个 Agent 在真实协作、赛事 Token Plan 模型确已调用、输出能转化为行动。

## 录制前检查

- PostgreSQL、Redis、后端和前端均已启动。
- `http://localhost:8080/api/health` 返回正常状态。
- 首页能打开，示例为 `Portable Blender / USA Amazon`。
- 浏览器缩放为 100%，窗口建议使用 1440 × 900 或 1920 × 1080。
- 关闭无关标签页、通知、密码管理器弹窗和开发者工具。
- 正式录制使用百炼 `qwen3.7-plus`，页面右上角应显示 `REAL AI`；另准备 Mock 模式作为现场兜底。
- 提前试导出一次 PDF，确认浏览器打印窗口可用。

讲解时不必逐字朗读页面，鼠标应跟随当前重点，避免快速滚动。

## 推荐操作流程

1. 打开 `http://localhost:5173`。
2. 保留预填商品 `Portable Blender` 和市场 `USA Amazon`。
3. 点击“开始 AI 分析”。
4. 在进度页等待四个 Agent 依次完成。
5. 在报告页先停留在机会评分，再缓慢滚动到用户痛点与策略区。
6. 点击“导出 PDF”，展示可交付结果。

## 无网络或模型异常预案

默认 Mock 模式就是正式演示预案，无需外网也能展示完整流程。若百炼模式临时失败：

1. 停止后端。
2. 设置 `AI_PROVIDER=mock` 后重新启动。
3. 刷新前端并重新创建分析任务。

Mock 与百炼共用同一套 Agent、数据库和 API 流程，因此切换不会改变演示结构。

## 录制完成后的提交检查

- 视频中未出现真实 API Key、终端历史、个人账号或通知。
- GitHub 仓库能按 README 从零启动。

- 视频链接具有评委可访问权限。
- README 中的架构图可正常渲染。
- 仓库未包含 `node_modules`、`dist`、`target`、`.m2` 或数据库数据文件。
- 项目名称、参赛团队名称和提交表单中的描述保持一致。
